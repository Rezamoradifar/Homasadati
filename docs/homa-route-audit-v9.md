## دامنه بررسی

مبنای کار: نسخه منتشرشده V8 (`7b5befbedafc34cfa2014a28a49e9eb3f236d9b3`)،
ساختار `app/` در Next.js، کامپوننت‌های مرتبط و استایل‌های نسخه‌های V3 تا V8.

فهرست ۲۴ فایل `page.tsx` کامل استخراج شده و با تست خودکار تطبیق داده می‌شود.
مسیرهای پویا یک قالب صفحه‌ای دارند؛ بررسی قالب به‌معنای بررسی بصری تک‌تک رکوردهای محصول یا محتوا نیست.

## یکپارچگی و الزامات حفظ‌شده

- آرم همان `site_logo` تنظیم‌شده است؛ هیچ فایل لوگویی تغییر نمی‌کند.
- هیچ فایل موتور پورسانت، دیتابیس، کیف پول، پرداخت یا سیاست تسویه تغییر داده نمی‌شود.
- شماره‌ها در صفحه‌های مالی از همان API و منطق اصلی می‌آیند.
- صفحه مقاله فقط محتوای منتشرشده دیتابیس را نشان می‌دهد؛ اگر slug نامعتبر باشد همان 404 رخ می‌دهد.
- خروجی CSV و مدیریت درخواست‌ها در صفحه Legacy با همان API اصلی باقی می‌ماند.
- فرم Unsubscribe همچنان از `POST /api/unsubscribe` استفاده می‌کند.
- ارائه پلن همچنان از `card-levels` و کنترل دکمه/صفحه‌کلید استفاده می‌کند.

## شواهد آزمون

- `app/homa-route-audit-v9.test.ts`: فهرست همهٔ ۲۴ مسیر، پوسته مشترک و رفتار مسیرهای مستقل.
- `app/homa-route-audit-v9.css`: قانون‌های اختصاصی هر نوع صفحه برای روشن/تیره و صفحه‌های ۳۸۰، ۷۶۷، ۱۱۹۹ پیکسل.
- GitHub Actions: `npm test`، بررسی متن و Build تولیدی.
- `scripts/homa-live-route-smoke.mjs`: ابزار خواندنیِ HTTP برای صفحات عمومی؛ **پس از انتشار** با فرمان زیر قابل اجراست:

  ```bash
  node scripts/homa-live-route-smoke.mjs https://homanets.com
  ```

  برای نمونه واقعی محصولات و مقاله‌ها می‌توان متغیرهای `HOMA_PUBLIC_PRODUCT_ID` و `HOMA_PUBLIC_CONTENT_SLUG` را تعیین کرد. ابزار فقط GET می‌فرستد، بدون ورود، پرداخت یا داده خصوصی. اجرای این ابزار روی سرور فعلی هنوز تأیید نشده است.


## محدودیت‌های بررسی

این مرحله **بازبینی و اصلاح کد و تست خودکار** است، نه تأیید تصویری همه صفحات روی مرورگر واقعی.
دسترسی مرورگری مستقیم به نسخه زنده، حساب کاربری تست و اسکرین‌شات اتوماتیک در این محیط برقرار نبود.
پس از انتشار، اسکرین‌شاتِ موبایل، لپ‌تاپ و دسکتاپ از مسیرهای پرتکرار برای مقایسه پیکسلی لازم است.
تست واقعی پرداخت، تحویل OTP و صفحات کاربرِ احراز هویت‌شده باید جداگانه انجام شوند.
