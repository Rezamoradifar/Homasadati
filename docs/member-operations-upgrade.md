# ارتقای نمایش مبالغ و رسیدگی به اعلان‌ها

این نسخه روی `9e5bf08992d8b9a5e84d89c54d578f614644f2ca` ساخته شده است.

## تغییرات

- مبلغ‌های نمایشی و ورودی‌های مالی پنل به ریال هستند. ذخیره‌سازی و API همچنان تومان هستند؛ فرم‌ها دقیقاً در مرز ورود و خروج تبدیل می‌کنند. تعداد جایگاه، کالا، امتیاز و درصد تبدیل نمی‌شوند. هر ورودی ریالی باید مضرب ۱۰ باشد تا واحد صحیح تومانی حفظ شود.
- اعلان‌های مالی جدید و متن خوش‌آمدگویی ریالی هستند. تاریخچهٔ پیام‌های قبلی بازنویسی نمی‌شود.
- وضعیت عمومی طرح از پاسخ موفق سرور خوانده می‌شود. بارگذاری یا خطای شبکه به معنی غیرفعال‌بودن طرح نیست؛ خطا دکمهٔ تلاش دوباره دارد. این نسخه طرح یا زمان‌بندی تسویه را فعال یا تغییر نمی‌دهد.
- بخش تنظیمات مدیر، فهرست صفحه‌بندی‌شدهٔ اعلان‌های نیازمند رسیدگی را نشان می‌دهد. نشانی گیرنده پوشانده شده و متن پیام برگردانده نمی‌شود.
- فقط مدیر اصلی می‌تواند پس از پایان تلاش‌ها و بررسی سابقهٔ ارسال، برای همان گیرنده یک تلاش دیگر ثبت کند. حداکثر سه تلاش دستی برای هر پیام وجود دارد؛ هر تلاش با دلیل و هویت مدیر ثبت می‌شود. شمارهٔ تلاش صفر نمی‌شود و ارسال هم‌زمان، دوبار کلیک و نتیجهٔ دیررس پردازشگر، مجوز ارسال اضافی ایجاد نمی‌کنند.
- گیرندهٔ تغییرکرده، اعلان غیرفعال‌شده، پیام ارسال‌شده و پیام لغوشده قابل ارسال مجدد نیستند. ثبت تلاش مجدد به معنی تحویل پیام نیست. نبود پاسخ سرویس می‌تواند با ارسال موفق همراه باشد؛ بررسی پنل ارائه‌دهنده پیش از تلاش دستی لازم است.
- ماژول‌های مدیریت و تب‌های فرعی هنگام نیاز بارگذاری می‌شوند.
- رابط مدیریت به‌صراحت نشان می‌دهد استعلام خودکار هویت/مالکیت حساب متصل نیست؛ ثبت مرجع بررسی کارشناس جای اتصال رسمی را نمی‌گیرد.

## نصب

از `scripts/deploy-zibal.sh` در نسخهٔ دقیق منتشرشده، با هر دو گزینهٔ `--skip-merchant --preserve-schedule` استفاده کنید. نصب قبلی را هم‌زمان دوباره اجرا نکنید. نصب با قفل انحصاری، ساخت جداگانه، تست‌ها، بکاپ و بازگشت در خطا انجام می‌شود؛ تغییرات محلی ناشناخته متوقفش می‌کنند.

پس از نصب، در تنظیمات مدیر وضعیت worker، بکاپ محلی، بکاپ خارج از سرور و پایش را بررسی کنید. `/api/health` فقط زنده‌بودن وب را نشان می‌دهد و تأیید پرداخت، پیامک یا بکاپ نیست.

## کارهایی که به سرور و سرویس واقعی نیاز دارند

1. نتیجهٔ کامل نصب و آخرین بخش لاگ باید موفق باشد. در نصب قبلیِ ارسالی مالک، فایل لاگ `/root/homa-upgrade.pnUVPYWQ.log` بود؛ تصاویر، پایان نصب را نشان نمی‌دادند.
2. بکاپ تازه و آزمون بازیابی طبق `docs/OPERATIONS.md` اجرا شود. بازیابی آزمایشی فقط کپی موقت را باز می‌کند و پایگاه‌داده زنده را جایگزین نمی‌کند. بکاپ خارج از سرور نیازمند مقصد واقعی Restic است.
3. تحویل هشدار به مقصد واقعی و پایش از بیرون VPS بررسی شود. اطلاعات خصوصی مقصد فقط در `/etc/homay/operations.env` قرار می‌گیرد.
4. یک ثبت‌نام با دریافت واقعی کد، انتخاب محل دعوت، خرید واقعی کوچک، تأیید درگاه و ثبت سفارش بررسی شود. محیط آزمون این نسخه هیچ پیام واقعی یا خرید واقعی ایجاد نکرده است.
5. اتصال رسمی تطبیق هویت و حساب بانکی به نام ارائه‌دهنده، مستندات قرارداد API و دسترسی معتبر نیاز دارد. این نسخه چنین اتصال تأییدنشده‌ای را شبیه‌سازی نمی‌کند.

مستند API تلاش مجدد در `docs/openapi.json` ثبت شده است. هیچ کلید سرویس یا اطلاعات بانکی نباید در گزارش عمومی یا Pull Request قرار گیرد.

## نتیجهٔ بررسی این نسخه

- ۴۲۳ تست در ۷۸ فایل (شامل چهار تست نصب) موفق شدند؛ ساخت تولید و بررسی TypeScript موفق بود.
- پوشش ترجمهٔ انگلیسی برای ۳۲۸۲ متن بررسی شد و متن بدون ترجمه باقی نماند.
- جمع فایل‌های اولیهٔ جاوااسکریپت مسیرهای حساب و مدیریت در مانیفست ساخت محلی از ۸۱۶٬۶۳۴ به ۶۷۵٬۲۱۹ بایت رسید؛ حدود ۱۷٫۳٪ کاهش. این اندازهٔ فایل است، نه ادعای بهبود زمان بارگذاری روی اینترنت واقعی.
- تست‌های رابط ثبت‌نام، خرید از پنل و فروشگاه و ثبت سفارش با API واقعی و SQLite آزمایشی اجرا شدند. سرویس ارسال و درگاه واقعی استفاده نشدند.
- آزمون تصویری با مرورگر موبایل اجرا نشد: فایل اجرایی Chromium موجود نبود و دانلود مرورگر شکست خورد. بررسی روی گوشی واقعی پس از نصب باقی است.
- پاسخ عمومی سلامت سایت هنگام بررسی `ok` بود؛ از این پاسخ نمی‌توان پایان ارتقا، تحویل پیام، صحت بکاپ یا پرداخت واقعی را نتیجه گرفت.
