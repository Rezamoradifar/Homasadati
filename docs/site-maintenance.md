# حالت به‌روزرسانی سایت هما نت

این نسخه به درخواست مالک، **به‌صورت پیش‌فرض با حالت به‌روزرسانی روشن** اجرا می‌شود. صفحات عمومی از همان نشانی درخواست‌شده، صفحه مستقل `public/site-maintenance.html` را با وضعیت HTTP `503` نمایش می‌دهند. پاسخ شامل `Retry-After: 300`، `Cache-Control: no-store, max-age=0` و `X-Homa-Maintenance: active` است. مقدار `Retry-After` فاصله پیشنهادی برای درخواست مجدد است و زمان پایان به‌روزرسانی را اعلام نمی‌کند.

صفحه از لوگوی موجود و فونت‌های محلی استفاده می‌کند و برای نمایش به اجرای React یا دریافت فونت از سرویس بیرونی وابسته نیست. مشخصات فایل‌های فونت و مجوز همراه آن‌ها در [راهنمای فونت‌ها](../public/fonts/README.md) ثبت شده است.

## روشن، خاموش و مشاهده وضعیت

دستورها برای نصب موجود در `/opt/homay/app` و کاربر سرویس `homay` هستند و از پوسته مدیر سرور اجرا می‌شوند. اسکریپت، مسیر پروژه را از محل خودش تعیین می‌کند؛ نیازی به تغییر پوشه جاری نیست. اجرای آن با کاربر `homay` دسترسی فایل وضعیت را با کاربر برنامه هماهنگ نگه می‌دارد.

مشاهده وضعیت فعلی:

```bash
runuser -u homay -- node /opt/homay/app/scripts/site-maintenance.mjs status
```

روشن‌کردن صفحه به‌روزرسانی:

```bash
runuser -u homay -- node /opt/homay/app/scripts/site-maintenance.mjs on
```

بازگرداندن نمایش عادی سایت:

```bash
runuser -u homay -- node /opt/homay/app/scripts/site-maintenance.mjs off
```

تغییر روی درخواست بعدی اعمال می‌شود و به build، restart یا تغییر فایل‌های محیطی نیاز ندارد. تغییر وضعیت، صفحه‌ای را که از قبل در مرورگر باز است خودکار بارگذاری مجدد نمی‌کند.

خروجی JSON شامل `enabled`، `source` و مسیر فایل است:

| مقدار `source` | معنی |
| --- | --- |
| `default` | فایل وضعیت وجود ندارد؛ حالت به‌روزرسانی روشن است. |
| `override` | مقدار بولی `enabled` از فایل وضعیت خوانده شده است. |
| `invalid` | فایل قابل خواندن نیست یا محتوای معتبر ندارد؛ حالت به‌روزرسانی روشن می‌ماند و دستور `status` با کد خروج ۱ تمام می‌شود. |

## فایل وضعیت و ماندگاری آن

انتخاب محلی در `data/site-maintenance.json` نگهداری می‌شود. middleware مبتنی بر Node.js این فایل را در هر درخواست مشمول حالت به‌روزرسانی دوباره می‌خواند؛ وضعیت داخل build یا حافظه برنامه ثابت نمی‌شود. فقط مقدار بولی `true` یا `false` معتبر است. نبود فایل به پیش‌فرض روشن برمی‌گردد؛ خطای خواندن، JSON نامعتبر یا نوع نادرست مقدار هم صفحه به‌روزرسانی را روشن نگه می‌دارد.

اسکریپت کنترل، فایل جدید را در همان پوشه می‌نویسد و سپس به‌صورت اتمیک جایگزین می‌کند. فایل، حاوی وضعیت غیرمحرمانه و زمان تغییر است. پوشه `data/` در Git نادیده گرفته می‌شود و installer موجود هنگام تعویض کد و build آن را حفظ می‌کند؛ در Compose نیز همین پوشه روی volume پایدار قرار دارد.

بنابراین یک انتخاب قبلی `off` بعد از restart یا انتشار نسخه جدید هم باقی می‌ماند. پس از نصب این نسخه، برای فعال‌سازی موردنظر، ابتدا `status` و در صورت نیاز `on` را اجرا کنید. حذف فایل، راه خاموش‌کردن نیست و به پیش‌فرض روشن برمی‌گردد. پس از پایان کار، با `off` نمایش عادی را برقرار و پاسخ HTTP را بررسی کنید.

## مسیرهایی که در دسترس می‌مانند

استثناها فقط مسیر دقیق یا زیرمسیر آن را پوشش می‌دهند؛ مثلاً `/admin` مجاز است ولی `/administrator` استثنا نیست. احراز هویت و مجوزهای قبلی هر مسیر همچنان اجرا می‌شوند.

| مسیر | رفتار هنگام به‌روزرسانی |
| --- | --- |
| `/api` و زیرمسیرها | APIها، ورود، سلامت سرویس و callbackهای پرداخت با رفتار قبلی ادامه دارند. |
| `/admin` و زیرمسیرها | پنل و ورود مدیر با کنترل دسترسی موجود در دسترس می‌مانند. |
| `/payment/result` و زیرمسیرها | صفحه نتیجه پرداخت و استعلام‌های مجاز آن در دسترس می‌مانند. |
| `/unsubscribe` و `/legal` و زیرمسیرها | لغو عضویت و اسناد حقوقی در دسترس می‌مانند. |
| `/assets`، `/fonts`، `/_next/static`، `/_next/image` و زیرمسیرها | منابع لازم برای نمایش صفحه به‌روزرسانی و مسیرهای مجاز ارائه می‌شوند. |
| `/favicon.ico`، `/icon.png` و `/apple-icon.png` | نمادهای سایت ارائه می‌شوند. |

سایر صفحات، از جمله `/`، `/shop`، `/cart`، `/account` و `/worlds/...`، پاسخ به‌روزرسانی می‌گیرند. لینک‌های صفحه نتیجه پرداخت به حساب، سفارش‌ها، پشتیبانی، سبد خرید یا فروشگاه نیز به این محدودیت می‌رسند. اگر نشست مشتری منقضی شده باشد، ورود از `/account` در این بازه در دسترس نیست؛ callbackهای پرداخت همچنان اجرا می‌شوند.

این قابلیت نمایش صفحات عمومی را کنترل می‌کند. APIهای مجاز و worker به کار ادامه می‌دهند و کاربران دارای نشست یا صفحه باز قبلی ممکن است همچنان درخواست API بفرستند. فعال‌کردن آن توقف ثبت سفارش، عملیات مالی یا نوشتن در دیتابیس را تضمین نمی‌کند.

## بررسی پس از فعال‌سازی و رفتار پایش

برای مشاهده وضعیت صفحه اصلی و هدرها، بدون گزینه `--fail` درخواست بفرستید، چون `503` پاسخ مورد انتظار حالت روشن است:

```bash
curl -sS -D - -o /dev/null https://homanets.com/
curl -fsS https://homanets.com/api/health
```

در حالت روشن، صفحه اصلی باید `503` و هدر `X-Homa-Maintenance: active` داشته باشد. `/api/health` در حالت سالم همچنان `200` و `{"status":"ok"}` برمی‌گرداند؛ این پاسخ به‌تنهایی موفقیت پرداخت، worker یا بکاپ را تأیید نمی‌کند. `/api/health/ready` کنترل توکن قبلی را حفظ می‌کند و درخواست بدون توکن همچنان `401` می‌گیرد. برای خاموش‌کردن، پس از اجرای `off` بازگشت پاسخ عادی صفحه اصلی را بررسی کنید.

اسکریپت‌های موجود `scripts/external-monitor.mjs` و `scripts/homa-live-route-smoke.mjs` برای صفحات عمومی انتظار `200` دارند. در نتیجه، هنگام به‌روزرسانی عمداً نتیجه ناموفق می‌دهند و ناظر بیرونی، در صورت نصب و پیکربندی اعلان، ممکن است هشدار بفرستد. این نسخه آن اسکریپت‌ها یا تنظیمات پایش را تغییر نمی‌دهد. در بازه نگهداری، `503` مورد انتظار صفحه عمومی را با وضعیت API سلامت جداگانه ارزیابی کنید؛ هر پاسخ `503` را نشانه سالم‌بودن سرویس در نظر نگیرید.

آزمون `src/platform/site-maintenance.test.ts` به فهرست آزمون‌های متمرکز installer افزوده شده است. نصب و آزمون محلی، جای بررسی پاسخ‌های واقعی دامنه و مشاهده صفحه پس از انتشار را نمی‌گیرد.
